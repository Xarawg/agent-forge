# UX-спецификация редизайна веб-UI agent-forge — v1 (release depth)

Основание: `docs/UI_SPEC.ru.md` + решения Q-01…Q-11 (Q-01…Q-09 одобрены
2026-08-26 «принято всё»; Q-10, Q-11 — доработки владельца на финальном
гейте 2026-08-26).
Философия, к которой трейсится каждое решение: **контроль важнее автономии** —
UI честно показывает состояние. Мутации — только явно одобренные владельцем:
существующий `/wizard/save` и гейт-действия accept/resume (Q-10), причём
каждое гейт-действие проходит через модальное окно с объяснением последствий
и параллельно всегда доступно как «команда + копировать» (Q-06).

## 1. Информационная архитектура

```
forge ui (http://127.0.0.1:8765)
├── /  index.html — единственная клиентская страница (SPA без роутера)
│     ├── Шапка (sticky)
│     │     ├── лого «agent-forge»
│     │     ├── селект прогона
│     │     ├── мета прогона: provider · mock · started_at
│     │     ├── прогресс «Сделано N из M» + бар
│     │     ├── стоимость «$X.XXXX»
│     │     ├── индикатор живости: ● обновлено HH:MM:SS
│     │     ├── вкладки: Канбан | Отчёт
│     │     └── переключатель RU | EN
│     ├── Баннер «⏸ Прогон ждёт решения» (только при gate_wait ≠ null)
│     │     └── кнопки: «копировать» + «Выполнить…» → модальное окно (Q-10)
│     ├── Вид «Канбан»: 7 колонок + extra
│     ├── Вид «Отчёт»: сводка + таблица + блок «простым языком»
│     ├── Drawer событий задачи (overlay, справа / на весь экран)
│     └── Модальное окно подтверждения гейт-действия (Q-10)
└── /wizard?file=… — серверная страница (как сейчас), рестайл
```

Принципы:
- Один `index.html`, ноль внешних ресурсов (Q-рамка «офлайн»).
- Все данные — через существующие GET-ручки + read-only расширение (§3).
- Действия — POST accept/resume (Q-10) и существующий `/wizard/save`.
- Polling 3 с, пауза на скрытой вкладке (Q-09).

## 2. Дизайн-токены (Q-03)

--border: #2a2a2a    --text: #f0f0f0        --text-dim: #888888

--success: #2ea043   --warning: #d29922     --danger: #f85149
--font-body: Inter, -apple-system, "Segoe UI", Roboto, sans-serif (system stack, без загрузки)
--font-mono: SFMono-Regular, Consolas, "Liberation Mono", Menlo, monospace

Цвета состояний (7 + queued):

| running | `#79c0ff` (голубой из code-палитры site) | бордер, бейдж, «пульс» |

## 3. Контракт API (read-only расширение, Q-01/Q-02/Q-05)

`GET /api/run/<run_id>` — добавляются поля (всё остальное без изменений,
обратная совместимость сохранена):

```jsonc
{
  "run": { /* run.json целиком, как сейчас */ },
  "tasks": [ /* как сейчас: только задачи с journal-записями */ ],
  "totals": { /* как сейчас */ },

  "queue": [              // вся очередь из meta.tasks_path, топологический порядок
    {"id": "scan-repo", "title": "…", "gate": null},
    {"id": "port-validator", "title": "…", "gate": "review"}
    // задачи без journal-записей присутствуют здесь и отсутствуют в tasks[]
  ],
  "accepted": ["scan-repo"],        // meta.accepted или []
  "gate_wait": "port-validator",    // string | null — логика report._gate_wait
  "report_extra": {
    "cost_cap_total": 3.10,               // сумма max_cost_usd по очереди (null, если капов нет)
    "cap_verdict": "ok",                  // "ok" | "exceeded" | null
    "models_by_role": {"coder": "deepseek-chat", "reviewer": "deepseek-chat"},
    "prompts_version": "2026-08-19"
  }
}
```

- Битый/отсутствующий `tasks_path` → `queue: []`, `gate_wait: null`,
  `report_extra` с null-полями. Сервер не падает (§4.5 спеки).
- `GET /api/run/<id>/events`: лимит `note` 500 → **2000** (Q-07); `tail`
  без изменений (1…500).

### POST-ручки гейт-действий (Q-10, одобрено владельцем)

```
POST /api/run/<run_id>/accept    body: {"task_id": "<id>"}
POST /api/run/<run_id>/resume    body: {} (пустое)
```

- `accept` — та же логика, что `forge accept <task_id>`: merge ветки
  `forge/<task_id>` в текущую ветку целевого репо + запись задачи в
  `accepted` в run.json. Ответы: `200 {"ok": true}`; `409` при
  merge-конфликте или если задача не в состоянии гейта (`{"error": …,
  "stderr": …}`); `404` при невалидном run/task.
- `resume` — запускает `forge resume <run_id>` субпроцессом (detached,
  stdout/stderr в `runs/<id>/resume-ui.log`), сразу `202 {"ok": true}`;
  `409`, если прогон уже выполняется (lock-файл раннера).
- Обе ручки пишут в `runs/` **только через существующие механизмы
  runner'а/journal**, не напрямую. Path traversal — те же проверки `run_id`.
- UI вызывает `accept`, при успехе — `resume`; при ошибке accept резюм
  не вызывается.
- Полный список мутаций UI после Q-10: `/wizard/save` (существующая) +
  `accept` + `resume`. Всё остальное — read-only.

Клиентский merge: карточка строится из `tasks[]` (если есть журнал) или из
`queue[]` (призрачная, если журнала нет). Порядок внутри колонки — topo-порядок
`queue`, задачи вне очереди (журнал без tasks.yaml) — в конец, как в CLI.

## 4. Экран «Канбан»

### 4.1. Шапка

| Элемент | Данные | Поведение |
|---|---|---|
| Лого | — | статично |
| Селект прогона | `/api/runs` | как сейчас: дефолт — последний, выбор переживает polling; пункт: `run-… — package (N/M · $X)` |
| Мета | `run.provider`, `run.mock`, `run.started_at` | `deepseek · mock · 2026-08-26 09:15` |
| Прогресс | N = задачи в done (по queue), M = queue.length | «Сделано 3 из 7» + бар 160 px; при failed/blocked — подпись справа: «1 провалено · 1 заблокировано» (цвета состояний) |
| Стоимость | `totals.cost_usd` | `$1.2345`; при `cost_cap_total` — тонкий бар «потрачено / план» под числом, цвет success → warning (>80%) → danger (≥100%) |
| Живость | время последнего успешного fetch | зелёная точка + «обновлено 09:51:03»; при ошибке fetch — красная точка + «соединение потеряно, повтор…», контент остаётся, но шапка тускнеет (Q-09) |
| Вкладки | — | Канбан / Отчёт; активная — подчёркивание accent |
| RU/EN | localStorage `forge-ui-lang` | кнопка показывает *другой* язык (как на site: при RU кнопка «EN») |

### 4.2. Баннер gate-wait (Q-01 + Q-10, приоритет №1)

Показывается, когда `gate_wait ≠ null`. Sticky под шапкой, фон `surface`,
левая кромка `--line` accent, иконка ⏸.

```
⏸ Прогон ждёт решения — задача port-validator принята reviewer'ом и ждёт гейт №3.
   forge accept port-validator && forge resume run-20260826-091503
   [копировать]  [Выполнить…]
```

- Команда — mono-блок, клик по «копировать» → clipboard + подтверждение
  «скопировано ✓» на 1,5 с (текст кнопки меняется, без toast-библиотек).
- **«Выполнить…»** — primary (accent), открывает модальное окно
  подтверждения (§4.3). На узком экране кнопки переносятся под команду,
  обе на всю ширину.
- Гейт-задача на канбане одновременно получает бейдж «⏸ ждёт accept»
  (accent) и рамку accent вместо бордера состояния.
- Если `accepted` содержит задачу — на её карточке бейдж «✓ принято» (success).
- Баннер один даже при нескольких гейтах (логика `_gate_wait` возвращает
  первый) — совпадает с CLI.

### 4.3. Модальное окно подтверждения гейт-действия (Q-10)

Открывается по «Выполнить…» из баннера или из блока «простым языком».
Overlay с затемнением (`rgba(0,0,0,.6)`), центрированная карточка
max 560 px (на <600 px — на весь экран с отступами 12 px), закрытие:
«Отмена», Esc, клик по фону (в состоянии «выполняется» закрытие
блокируется).

Структура — три секции, строго в этом порядке:

1. **Что делали** — сводка по задаче из журнала: пайплайн
   `coder → validate → review` (пройденные фазы с ✓), стоимость и токены,
   repair-итерации, ветка `forge/<task_id>`, последний коммит (фаза git
   из событий).
2. **Что сделано** — факты текущего состояния: задача в `done`, reviewer
   одобрил, ветка закоммичена локально (push не выполняется никогда),
   прогон приостановлен на гейте №3.
3. **Что будет сделано при одобрении** — нумерованный список:
   1. `forge accept <id>` — merge ветки `forge/<id>` в текущую ветку
      целевого репо; задача записывается в `accepted`;
   2. `forge resume <run>` — прогон продолжится: следующие задачи очереди
      (их число — из `queue`) начнут выполняться и **тратить бюджет** в
      пределах капов (показать `cost_cap_total`);
   3. предупреждение (warning-кромка): при merge-конфликте accept
      завершится ошибкой, прогон останется на гейте — разрешите конфликт
      в терминале.

Кнопки: «Отмена» (ghost, default focus) и «Подтвердить: accept + resume»
(primary accent). Состояния:

- **выполняется** — спиннер + «выполняется accept…», кнопки disabled,
  закрытие заблокировано;
- **успех** — зелёная полоса «задача принята, прогон продолжен», модальное
  закрывается через 1,2 с само; баннер исчезает на следующем polling
  (данные придут сами — оптимистичного локального стирания нет);
- **ошибка** — красная полоса с текстом `error`/`stderr` из ответа,
  модальное остаётся открытым, кнопки снова активны (можно повторить или
  отменить).

### 4.4. Колонки и карточки

- 7 колонок в `STATE_ORDER` + extra-колонки (наследие) в конец — как сейчас.
- Заголовок колонки: рус/англ label + счётчик; ненулевые failed/blocked —
  счётчик цветом состояния.
- **Обычная карточка** (задача с журналом): title (600), id mono dim,
  бейджи: `⛳ gate`, `⏸ ждёт accept` / `✓ принято`; строка статов mono:
  `$0.4210 · 12.3k+4.1k tok · repair 1`; note — максимум 3 строки с
  line-clamp (полный текст — в drawer).
- **Призрачная карточка** (в queue, без журнала; Q-02): title/id/gate из
  tasks.yaml, пониженная контрастность (opacity .55, пунктирный бордер),
  плашка «ещё не запускалась», **без** статов и **без клика** (журнала нет —
  drawer не открывается, курсор обычный).
- Клик по обычной карточке → drawer (§6). Клавиатура: карточка focusable,
  Enter открывает drawer.

### 4.5. Состояния экрана

| Состояние | Рендер |
|---|---|
| Прогонов нет | пустое состояние: «Прогонов пока нет — запустите `forge run`» + copy-кнопка команды |
| Прогон есть, задач нет | «В прогоне пока нет задач — журнал появится после старта первой» |
| Битый run.json | мета «? · ?», канбан по доступным данным, без баннера |
| `queue` пуст (битый tasks_path) | прогресс «— из —», призрачных карточек нет, остальное работает |
| Ошибка fetch | контент не стирается; индикатор живости красный (Q-09) |
| Extra-состояния | extra-колонки в конец, label = сырое имя состояния |

## 5. Экран «Отчёт» (вкладка)

### 5.1. Сводка (карточки поверх таблицы)

Три плашки в ряд (на узком — стеком):
1. **Стоимость**: `$1.2345 из ~$3.10 (сумма капов)` + бар + вердикт
   «OK» (success) / «ПРЕВЫШЕНИЕ» (danger) по `cap_verdict`.
2. **Прогресс**: «Сделано 3 из 7 · 1 провалено · 1 заблокировано · 2 в очереди».
3. **Воспроизводимость**: модели по ролям (`coder: deepseek-chat`,
   `reviewer: deepseek-chat`), версия промптов — из `report_extra`;
   отсутствующие поля — «—».

### 5.2. Таблица задач

Как сейчас (ID, Задача, Состояние, Токены, Стоимость, Repair, Заметка) +
строка «Итого»; **все** задачи очереди: призрачные queued — строками с
прочерками в числовых колонках и пометкой «ещё не запускалась». Состояние —
цветной бейдж. Строка гейт-задачи подсвечена accent-кромкой слева.

### 5.3. Блок «простым языком» (Q-05, пробел 6)

Секция под таблицей, четыре списка (аналог `forge report --plain`):
- **Получилось** ✅ — done-задачи (title + $).
- **Не получилось** ❌ — failed/blocked (title + note, 1 строка).
- **Ждёт решения** ⏸ — gate_wait-задача + команда accept/resume + кнопки
  «копировать» и «Выполнить…» (модальное §4.3).
- **Что дальше** → — автогенерация по правилам CLI: гейт → accept+resume;
  failed → «разберитесь с <id> и перезапустите»; всё done → «прогон
  завершён»; иначе «прогон в работе / остановлен — `forge resume <run>`».

Пустые разделы не рендерятся. Если все четыре пусты (задач нет) — блок
скрыт целиком.

## 6. Drawer событий задачи (Q-07, приоритет №4)

### 6.1. Геометрия

- ≥1200 px: фиксированный drawer справа, 40% ширины (min 400 px, max 640 px),
  канбан под ним не перекрывается критично (overlay поверх, как сейчас).
- <1200 px: overlay на весь viewport с затемнением фона; закрытие — ✕, Esc,
  клик по затемнению.
- Открытие/закрытие — transform .15s, без bounce.

### 6.2. Контент

Шапка drawer: title задачи + id mono + бейдж состояния + ✕.
Тело — **список блоков событий** (не сплошной `<pre>`):

```
┌ 09:41:12 · coder/step 3                              tok 8.2k+1.1k · $0.0312 ┐
│ $ write_file src/api/v2/handlers.py                                        │
│ note: обновил обработчики под v2-контракт…                                 │
└─────────────────────────────────────────────────────────────────────────────┘
```

- Строка меты: ts (только время, дата — в title-подсказке), фаза/роль,
  exit-код (цвет: 0 — dim, ≠0 — danger), токены/$ — mono, выравнивание вправо.
- Команда — отдельный mono-блок на `surface`, `overflow-wrap: anywhere`,
  `word-break: break-word` — **горизонтальный скролл исключён** при любой
  длине команды/URL.
- note: до 2000 символов (Q-07); >420 символов — свёрнуто с кнопкой
  «развернуть / свернуть» (клиентская, без доп. запросов).
- Автопрокрутка вниз при открытии; если пользователь проскроллил вверх —
  новые события не дёргают скролл (флаг «прилип к низу»).
- Пустой журнал: «событий нет». Ошибка fetch событий: блок «не удалось
  загрузить журнал — повтор при следующем обновлении», drawer не закрывается.
- Drawer обновляется тем же polling 3 с; при смене прогона закрывается
  (как сейчас).

## 7. Экран «Wizard-форма» (Q-08)

Серверная страница, архитектура без изменений. Рестайл в токенах §2:

- Шапка: лого, имя файла mono, RU/EN (тот же словарь, сервер рендерит оба
  варианта через data-i18n + inline JS-переключатель).
- Прогноз: плашка «не больше ~$3.10 (сумма капов)» + подсказка команды
  `forge run --tasks … --target .` с copy-кнопкой.
- Lint-предупреждения — alert-полосы с warning-кромкой, перед карточками.
- Карточка задачи: fieldset'ы title / spec_ref / scope_paths / acceptance /
  max_tokens / max_cost_usd / gate; mono для путей и команд; `depends_on`
  показан read-only плашкой «наследуется из файла».
- «Сохранить черновик» — primary (accent). Результат: зелёная полоса
  «сохранено» / красная «ошибка контракта: …» (как сейчас, в токенах).
- Нельзя: добавить/удалить задачу, менять порядок и depends_on (без изменений).

## 8. Адаптивность (Q-07, мобильный канбан — Q-11)

| Ширина | Поведение |
|---|---|
| ≥1200 px | канбан: колонки flex, min 220 px; drawer 40% |
| 768–1200 px | канбан: горизонтальный скролл контейнера (норма для канбана); drawer — полноэкранный overlay |
| <768 px | шапка в 2 ряда (селект+вкладки / мета+прогресс+стоимость); **канбан — вариант B (аккордеон)**, A — задокументированная альтернатива; сводка отчёта стеком; drawer — overlay; модальное §4.3 — на весь экран с отступами |

### Мобильный канбан <768 px (Q-11, выбор владельца: B)

Горизонтальный scroll-snap по колонкам отклонён: две оси прокрутки, узкие
карточки, колонки вне viewport невидимы. Владелец рассмотрел оба варианта
в ui-board (переключатель A/B) и **выбрал B (2026-08-26)**.

**Вариант B — «Аккордеон пайплайна» (ОСНОВНОЙ).**
- Вертикальный список секций в порядке пайплайна; заголовок = состояние +
  счётчик + шеврон; раскрытие показывает карточки (можно несколько секций).
- Дефолтно раскрыта секция «внимания»: gate-wait → failed/blocked →
  running → validating/review → done → queued.
- Сохраняет обзор всей «трубы» одним скроллом — владельцу видны все
  состояния без переключений; ценой длины страницы при многих раскрытых.

**Вариант A — «Чипы состояний + один список» (задокументированная
альтернатива, не реализуется в v1).**
- Горизонтальная полоса чипов `Состояние · N` + один вертикальный список
  карточек выбранного состояния; дефолтный чип — «внимание» (тот же
  приоритет). Компактнее, но скрывает обзор пайплайна за переключением.

**Общее для мобильного:** drawer — полноэкранный overlay; баннер gate-wait
прижат кверху (под шапкой); жесты/свайпы не вводим — нативный скролл.

Горизонтального скролла на мобильном нет вообще (вариант B — чисто
вертикальный); внутри карточек, drawer, модального и таблицы отчёта — тем
более никогда (таблица на <768 px — карточный вид: строка превращается в
блок с подписанными полями).

## 9. i18n (Q-04)

- Словарь `I18N = {ru: {…}, en: {…}}` в начале `<script>`, атрибуты
  `data-i18n="key"`; дефолт — `ru`; выбор в `localStorage["forge-ui-lang"]`.
- Переводятся: заголовки колонок, вкладки, баннер, бейджи, пустые состояния,
  сводка отчёта, «простым языком», кнопки, wizard. **Не переводятся**:
  контент данных (title, note, команды, id, имена провайдеров).
- Динамические строки — через функции-шаблоны:
  `t("progress", {n, m})` → ru: `Сделано ${n} из ${m}`, en: `${n} of ${m} done`.
- `document.documentElement.lang` переключается; даты/время — как в данных
  (ISO из журнала), без локализации формата.

## 10. Доступность и мелочи

- Карточки и кнопки — нативные `<button>`/`<a>` или `tabindex="0"` + Enter.
- Esc закрывает drawer; фокус возвращается на карточку-триггер.
- Цвет состояния всегда дублируется текстом/иконкой (бейдж с подписью) —
  не полагаемся на цвет alone.
- `prefers-reduced-motion`: отключаются transition drawer и пульс running.
- Экранирование: весь контент данных через `esc()` (как сейчас) — без
  исключений для новых блоков (баннер рендерит id задачи тоже через esc).
