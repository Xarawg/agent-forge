# Стадия 1 — аудит спеки

Аудит `docs/UI_SPEC.ru.md` (v текущей, от 2026-08) под задачу редизайна UI:
противоречия, недостающие данные, конфликты с зафиксированными рамками.

Метод: каждая находка классифицирована по severity (blocker/major/minor) и
impact (UX/UI/dev); для каждой — предложенное решение с rationale, точными
правками спеки и одной альтернативой. Собрано в `PROPOSED_DECISIONS.md`
(ID Q-01…Q-09).

**Гейт:** стадия 2 не начинается, пока владелец не ответит «принято всё»,
по-ID правками или пакетными одобрениями.

Ключевой факт аудита (проверен по коду): приоритетные улучшения №1 и №2
(«ждёт accept», «N из M») **невозможны на чистом клиенте** — `/api/run/<id>`
не отдаёт полную очередь из tasks.yaml (топологический порядок) и список
`accepted` из run.json. Детекция гейта живёт в `forge/report.py::_gate_wait`
(строки 100–116) и требует обоих. Нужно read-only расширение API (сервер
ничего не пишет в `runs/` — рамка read-only не нарушается).
