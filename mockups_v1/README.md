# mockups_v1 — редизайн веб-UI agent-forge

Итерация UX/UI по пайплайну `ux-mockup-pipeline`. Входной концепт-документ:
`docs/UI_SPEC.ru.md` (спека текущих возможностей и пробелов). Референс стиля:
`site/index.html`. Текущая реализация (только как чек-лист покрытия, не как
дизайн-база): `forge/ui_static/index.html`, `forge/ui.py`.

## Зафиксированные рамки (не пересматриваются)

1. **Read-only к `runs/`**. Действия из UI — только там, где они уже есть
   (редактор черновика `/wizard`), либо явно одобрены владельцем на гейте.
2. **Офлайн**: без CDN, один самодостаточный `index.html` (+ локальные ассеты).
3. **Тёмная тема в духе `site/`** (токены: `#0a0a0a`, акцент `#d40027`,
   sharp radius 3px, mono для данных).
4. **Переключатель рус/англ** (паттерн `data-i18n` как на `site/`).
5. Приоритетные улучшения (из §3 спеки):
   - видимость «прогон ждёт accept» на канбане (пробел 1);
   - честный прогресс «N из M» (пробел 5);
   - стоимость прогона наглядно;
   - журнал задачи без горизонтального скролла (пробел 14 частично).

Философия продукта, к которой трейсятся UX-решения (из README/SPEC):
контроль важнее автономии — человеческие гейты, честные остановки, полный
аудит, никаких скрытых мутаций. UI обязан **показывать** состояние честно,
а не **управлять** прогоном.
